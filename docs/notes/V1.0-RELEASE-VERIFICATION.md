## End-to-End Distribution Verification

The generated distribution ZIP was extracted into a temporary directory outside the repository. Runtime state and private data used separate temporary `LOCALAPPDATA` and `APPDATA` directories.

The packaged `mini-server.jar` and `lib/*` were run with local OpenJDK `1.8.0_492`. The successful run used operating-system-selected port `44099` and verified:

- the listener was bound only to loopback `127.0.0.1` (reported by `ss` as its IPv4-mapped loopback representation);
- `/example/` and `/_shared/mini-api.js` returned `200`;
- the example's bundled `start` Section returned `"Hello Mini Webserver"`;
- shared and private example scopes each completed write, read, readAll, remove, and clear operations;
- `/example/data/data.json` returned `404` without exposing persistence content;
- `miniweb-template.zip` was extracted to `www/t014-template-test/`;
- the template HTML and JavaScript loaded, referenced the shared MiniApi, and used `MiniApi.read("start").shared()`;
- the template starter value returned `"Hello Mini Webserver"` and an actual shared persistence write/read round trip succeeded;
- the packaged stop command stopped the server, removed active state, and allowed the Java process to exit cleanly.

Browser UI clicking was not performed in the Linux environment. The browser-facing behavior is covered by the packaged HTTP/API run, the 22 MiniApi JavaScript tests, example/template source inspection, and the supplied manual Windows Edge evidence.

Distribution inspection additionally verified:

- all 54 production class files and all 54 packaged production class files have major version 52;
- Gson 2.14.0 has 221 Java-8-visible classes with maximum major version 52;
- error_prone_annotations 2.48.0 has 29 Java-8-visible classes with maximum major version 52;
- `start.bat` and `stop.bat` use CRLF line endings;
- runtime dependencies are present while JUnit/test-only dependencies are absent;
- `template/`, `target/`, runtime locks/state, and private user data are absent from the distribution;
- the launchers use the current `javaw`/`java` design without `pushd`, `popd`, a second control listener, PID files, launcher handshakes, or a process supervisor.
