# V1.1 Note — Browser Fallback

Status: Future consideration for Mini Server v1.1

This note records a browser-launch improvement deliberately postponed until after the Mini Server v1.0 release.

It is not part of the v1.0 implementation scope and must not change the current T-010 requirements or implementation.

## Current v1.0 Behavior

Mini Server v1.0 uses Microsoft Edge as the intended browser on Windows.

After Mini Server has started successfully, the browser-launch logic constructs the local application URL from:

    127.0.0.1
    the actual active server port
    the configured start target

Example:

    http://127.0.0.1:51847/example/

Mini Server then attempts to open Microsoft Edge with that URL.

## Edge Not Available

If Microsoft Edge is not available or cannot be started, this must not invalidate or terminate an otherwise successfully running Mini Server instance.

The server continues running normally.

The browser-launch failure must not:

- stop the server;
- invalidate runtime state;
- change the active port;
- start another server;
- modify persistence data.

The complete local URL must remain available so that the user can open it manually in another browser.

Example diagnostic:

    Mini Server started on 127.0.0.1:51847

    Microsoft Edge could not be started.

    Open this URL manually:

    http://127.0.0.1:51847/example/

## Repeated Start

The same principle applies when Mini Server is already running.

A repeated start should:

1. detect the existing Mini Server instance;
2. obtain its active port;
3. construct the correct local application URL;
4. attempt to open Microsoft Edge.

If Edge cannot be started:

- the existing Mini Server instance remains untouched;
- the complete URL is shown to the user;
- the repeated-start process may terminate normally afterwards.

## Proposed v1.1 Improvement

A future Mini Server v1.1 may provide an automatic browser fallback.

The intended behavior could be:

    Microsoft Edge available
        -> open Microsoft Edge

    Microsoft Edge unavailable or launch fails
        -> open the Windows default browser

The active Mini Server URL must remain identical regardless of which browser is used.

Example:

    http://127.0.0.1:<active-port>/<site>/

The fallback browser must never influence:

- server startup;
- dynamic port allocation;
- runtime locking;
- persistence behavior;
- application routing.

## Failure of Both Browser Launch Methods

If neither Microsoft Edge nor the Windows default browser can be opened, Mini Server should continue running.

The complete local URL must then be displayed clearly for manual use.

A browser-launch failure is therefore a convenience failure, not a server failure.

## Scope Boundary

This automatic browser fallback is intentionally postponed until Mini Server v1.1.

Mini Server v1.0 should be completed using the already approved Microsoft Edge launch behavior.

Do not expand T-010 or the active v1.0 requirements in order to implement automatic fallback behavior.

When Mini Server v1.1 planning begins, this note should be reviewed and converted into the appropriate:

- requirement;
- architecture update;
- technical decision;
- implementation task.

The details described here are a design note for future planning and are not yet an approved v1.1 implementation contract.
