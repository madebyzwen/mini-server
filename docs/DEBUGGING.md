# Debugging

This document records reusable debugging information for the project.

Only confirmed findings should be documented here.

Do not record assumptions, guesses, or temporary hypotheses as established causes.

---

## Purpose

Use this document for problems that are likely to be relevant again during future development or maintenance.

Typical entries may include:

- Reproducible defects
- Environment-specific problems
- Runtime issues
- Build problems
- API failures
- File access problems
- Browser compatibility issues
- Platform-specific behavior
- Verified workarounds
- Confirmed root causes

Short-lived debugging notes that are not yet verified should remain in the current task context until they are confirmed.

---

## Entry Format

Use the following structure for each documented issue:

### Issue: Short descriptive title

#### Symptoms

Describe what the user or developer observes.

Include relevant error messages, behavior, or conditions.

#### Environment

Document relevant environment information if it affects the problem.

Examples:

- Operating system
- Java runtime
- Browser
- Build tool
- File permissions
- Network environment

#### Reproduction

Describe the smallest reliable procedure that reproduces the problem.

#### Cause

Document the confirmed root cause.

Do not describe an assumption as a confirmed cause.

If the cause is still unknown, state:

Cause not yet confirmed.

#### Verification

Describe how the cause was verified.

#### Fix

Document the verified solution or workaround.

#### Remaining Limitations

Document anything that remains unresolved or any limitations of the fix.
