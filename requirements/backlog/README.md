# Backlog Requirements

This directory contains requirements and ideas that may be implemented in the future but are not part of the current approved implementation scope.

Backlog items are not binding for current development.

They must not be treated as active requirements unless they are explicitly reviewed, approved, and moved to:

requirements/active/

## Purpose

Use this directory for requirements that:

- Are technically plausible
- May be useful in the future
- Are not currently approved for implementation
- Should be preserved for later review

A backlog requirement may be incomplete.

Missing details must not be interpreted as approved behavior.

## Workflow

When a backlog item becomes relevant for implementation:

1. Review the requirement.
2. Complete any missing details.
3. Confirm that it is approved for implementation.
4. Move it to requirements/active/.
5. Update requirements/INDEX.md.
6. Create or update implementation tasks as required.

When a backlog item is rejected permanently, it may either be removed or documented appropriately if preserving the historical decision is useful.

## Naming

Use the normal requirement naming convention:

REQ-<number>-<short-description>.md

Requirement identifiers must remain unique and must not be reused.
